# 页面滑动与切换性能专项测试

入口：设置 → 帮助与关于 → 性能排查 → 性能专项测试，也可搜索“性能测试”“掉帧”“CPU”。

专项范围是页面列表滚动、Pager 左右翻页、打开页面、返回和预测返回转场。播放器解码、缓冲和媒体丢帧暂不纳入。

入口提供默认关闭的“性能专项测试”开关：开启时确认采集范围，开启后滚动列表并反复打开、返回页面以复现问题，建议 3～5 分钟，再关闭开关结束并保存。可先打开同组的“查看性能摘要”，查看版本、设备、开始时间、结束状态、卡顿页面和问题时段，并复制整段摘要；再点击“分享性能报告”将 JSON 附件发送给开发者，并补充现象、步骤和大致时间。采集开启时显示的“标记刚才的问题”会记录时间点及前 30 秒的回看范围；标记发生在设置页，不能把标记页当成故障页。

会话按开始后的经过时间限制为 15 分钟。每个窗口只在其 Activity RESUMED 时采集界面帧和 HWUI。主窗口与独立详情窗口分别记录，父子窗口或分屏不会相互覆盖页面归属；进程资源始终只由一个生命周期作用域采样，所有窗口离开前台时暂停。后台后恢复会重置 CPU 区间，并沿用会话的资源采样节奏；如果在后台超过时限，返回时结束，不在后台启动计时服务。进程退出不自动恢复采集，可分享最近一次检查点。新会话覆盖旧报告。开关绑定当前进程的采集会话，不持久化为重启后自动开启；达到时限或存储失败时同步恢复关闭，设置搜索结果同步显示采集状态。采集不需要开启详细运行日志，不自动上传，不采集网络内容或完整导航参数。

## 报告 schema 4

- `environment`：版本、版本码、构建类型、debug 标记、设备型号、系统、CPU 核数及开始时的界面样式和玻璃开关。配置中途变化不会自动重写开始时的环境。
- `startedWallMs`：开始时间的 Unix 毫秒数；`startedMonotonicNs` 是开始时的单调纳秒时间。所有 `offsetMs` 都相对于它，不包含深度休眠，便于对齐 HWUI 帧时间。`elapsedMs` 包含后台和深度休眠，用于限制会话时长；`foregroundMs` 只累计前台采集时间。
- `stopReason`：`user` 主动结束、`time_limit` 达到时限、`storage_error` 存储错误。`checkpoint_unfinished` 表示尚未正常结束，不能据此判定一定发生崩溃。
- `frames`、`pages`、`scenes`：总体和各窗口主导航页面的帧数、JankStats 判定的卡顿帧数、比例、P50/P95/P99、最大 UI 帧耗时。无帧时比例和耗时为 `null`，不能当作性能良好。页面最多保留 48 类及 `other`，场景最多保留 64 类及 `other`。`pages` 的键为窗口 ID 和页面；`scenes` 的键为窗口 ID、页面和交互类型，交互分为 `scroll`、`transition`、`idle`、`unknown`。
- `samples`：前台约每 5 秒一次，最多 180 条。包含进程 CPU、Java 已用堆、Native 已分配堆、进程 PSS、省电模式和温控状态。温控在 API 29 以下为 `null`。`sampleIntervalMs`、`observedUiFrames`、`jankyUiFrames` 用于查看该段采样期间的界面绘制与卡顿；`windowId` 和页面字段取采样时最近恢复的前台窗口，`foregroundWindowIds` 列出所有 RESUMED 窗口；这些字段只是采样时的位置，该段内可能发生切页或切窗。窗口间合计帧数不能直接解释为任何单窗口的 FPS。
- `samples[].hwuiCumulative`：该采样点的 HWUI 累计帧数、截止时间可用帧数、错过截止时间帧数、回调丢失数及各阶段累计纳秒数和可用帧数。相邻点作差可观察问题时段的阶段平均耗时；阶段缺失不可当作 0。
- `samples[].display`：面板当前刷新率、窗口首选刷新率、首选模式 ID 和窗口焦点。窗口首选值 0 表示未明确指定；这些字段不等同于实际绘制帧率，也不覆盖所有 Surface 级刷新率请求。
- `markers`：最多 100 个人工问题标记。
- `latest100SlowUiFrames`：最近 100 个 UI 耗时至少 100ms 的帧及其时间、页面和白名单交互信号名称；不是全程最慢帧排行榜，也不是完整逐帧轨迹。

- `windows`：每个窗口的 ID、类型（`main`/`detail`）、是否已销毁、UI 帧与 HWUI 汇总。每窗的 `hwuiAvailable` 表示是否能开启硬件加速帧指标监听，尚未检查为 `null`。最多保留 32 个窗口，超出数记录为 `omittedWindows`，被省略窗口的帧不混入已记录窗口的分布。
- `windows[].navigation`：每窗最近 40 次导航运动；`observedNavigationMotions` 保留观察到的总次数。记录前后页面类型、操作类型（push/pop/replace/gesture_back 等）、观察起止时间、观察时长、UI 帧数/卡顿/P50/P95/P99 和 HWUI 帧数、错过截止帧数及 total/draw/GPU 峰值。使用匿名令牌区分导航实例，报告中只写静态页面类型，不写原始内容身份；同类型目的地变化也可分别记录。
- `navigation[].outcome`：`settled` 正常落位，`cancelled` 预测返回取消，`superseded` 被新的导航实例中断；`window_paused`、`window_destroyed`、`entry_disposed`、`user`、`time_limit` 等表示运动的观察被生命周期或采集结束截断。`startReason` 说明从真实运动开始边界、采集中途或窗口恢复中途开始观察。只有 `completeMotionBoundaries=true` 才同时具备完整的运动起止边界；其余 `durationMs` 仅为观察到的区间。无运动信号的目的地变化不会伪造动画时长。运动落位后迟到的帧，在采集仍开启时按时间区间回填，重复导出仍受最近 40 条保留范围限制。
- `windowHandoffs`：最近 100 次窗口恢复事件，包含来源/目标窗口和页面、恢复时间及恢复到首个 UI 帧的时间。未观测到符合时间条件的 UI 帧时为 `null`，不会写成 0；在首帧之前暂停、销毁或结束采集会标记相应状态。这是应用生命周期响应线索，不是系统跨窗口动画的完整耗时。
- `hwui`、`hwuiScenes`：独立 FrameMetrics 通道的总体和场景统计，场景最多 32 类及 `other`。阶段包括未知延迟、输入、动画回调、布局测量、绘制、同步、GPU 命令提交、缓冲交换、总耗时和 GPU 耗时，各自记录可用帧数及 P50/P95/P99/最大值。系统不提供的数据为 `null`。GPU 与截止时间字段需要 API 31+。`missedDeadlineFrames` 以总耗时超过系统提供的帧截止预算判定；`deadlineAvailableFrames` 才是该指标的分母，不与 JankStats 的 UI 卡顿分母混用。`droppedMetricCallbacks` 是监听回调丢失数，不是应用掉帧数。
- `latest100SlowHwuiFrames`：最近 100 个总耗时至少 100ms 或错过系统帧截止预算的帧，附带完整阶段明细、页面、场景及原始 intended-vsync 纳秒时间。UI 慢帧和 HWUI 慢帧是两条独立记录，不能按数组下标配对。

- `analysis.pageRanking`：按窗口与页面合并已记录的滚动和转场分组，用合并后的直方图重新计算百分位，不对百分位取平均。只排序实际出现 UI 卡顿的页面，按卡顿帧数、比例、最大 UI 耗时降序保留 10 项；同时提供分母与交互类型，不能把大样本页自然积累的更多卡顿当作更差的单位交互性能。idle、unknown、other 不进入此排序。
- `analysis.problemIntervals`：资源采样区间的前 10 个问题时段，按 UI 卡顿帧数和 HWUI 超期帧数降序；即使 UI 卡顿为 0，只要 HWUI 有超期仍保留。包含完整的单调时间起止、分母、CPU 和区间末尾位置；末尾位置不是整个区间的故障归属。HWUI 截止指标不可用时保持 `null`。
- `analysis.markedWindows`：每个人工标记前 30 秒范围内相交的完整采样区间；仅触碰边界的区间不算相交。未覆盖到采样区间时返回空列表，不能解释为该处没有问题；区间不做按时长比例估算，统计可能包含回看范围以外的部分。
- `analysis.summaryText`：中文可读摘要，可在应用内“查看性能摘要”中滚动阅读和复制，也可直接从 JSON 中查看，展示卡顿页面、卡顿时段和问题标记的具体统计；未采集项显示“未采集”，无记录时显示对应的空状态。

Compose 滚动通过各窗口导航宿主的 nested-scroll 观察实际被子列表或 Pager 消费的位移；原生 View（包括嵌入的网页）通过窗口 ViewTreeObserver 的滚动通知观察。两种监听均不消费额外手势。惯性滚动事件继续延长区间，最后一次位移后的 120ms 计为滚动尾段。既不发送 nested-scroll 位移、也不产生 View 滚动通知的自定义 Canvas 位移仍需专门埋点。导航转场使用真实的 `isRunning` 边界，包括预测返回及松手后的完成或取消动画，不用固定延时猜测结束。事件与帧使用同一单调时钟，并按帧的 UI 时间区间归类；转场优先于滚动。`idle` 仅表示未观测到这两类交互，不代表界面完全静止。边界与滚动区间各保留最近 256 条，旧上下文不可用时标为未知。

百分位使用固定 1ms 直方图，值为所在桶的上界；501 是“超过 500ms”标记，实际最大值另存。CPU 以单核 100% 计，多核可超过 100%。PSS、Java 堆和 Native 堆口径不同，不能直接相加。

## 排查方法与边界

先核对版本、构建类型和环境，再结合人工标记检查相邻采样区间的卡顿帧、CPU、PSS 和温控变化，最后按页面与滚动/转场场景汇总，以及慢帧交互信号缩小范围。静止页面仍出现大量 `observedUiFrames` 时，可进一步检查隐藏动画和无效绘制。

[JankStats](https://developer.android.com/topic/performance/jankstats) 复用 MainActivity 和 VideoActivity 已有的窗口监听，采集 UI 帧耗时并沿用默认卡顿判定。专项开启且处于前台时，另行注册公开的 [HWUI FrameMetrics](https://developer.android.com/reference/android/view/FrameMetrics) 阶段监听，关闭或进入后台即移除并退出专用回调线程。两路回调的数量可能不同，HWUI 分布以其实际收到的回调为分母。报告不提供视频解码丢帧、全系统调度轨迹或线程堆栈，不能仅凭某项数值证明根因。独立详情窗口中的页面滚动与导航已纳入；页面归属仍不精确代表分栏子视图和独立 Dialog 窗口。启动恢复页、登录授权等未接入的 Activity 不参与界面统计。系统跨 Activity 动画由窗口合成器驱动，不能用应用窗口的 HWUI 或 resume 到首帧时延替代其完整耗时。

debug 数据仅供诊断，不应与 release 数据直接比较或当作性能改进证据。采样、JSON 编码及磁盘保存也会产生开销；报告编码和存储放在 IO 线程，资源读取放在后台线程，逐帧只做有界统计。百分位计算与 JSON 编码在复制计数快照、释放统计锁后执行，避免报告编码长时间阻塞滚动和帧回调。正常每 5 秒及离开前台时保存原子检查点；进程卡死、强杀或存储失败时可能丢失更长区间。不要将检查点最后一条记录自动视为故障时刻。

HWUI 的 `draw` 是绘制命令记录耗时，`commandIssue` 是向 GPU 提交绘制命令耗时，不能把它们直接称为 GPU 执行时间，也不能把各阶段简单相加推断根因。GPU 耗时只取系统提供的 GPU_DURATION。进程级 CPU 与内存仍可能包含同时运行的媒体任务，报告不对这些资源做播放器归因。

应用内预览读取原子保存的同一份报告，在 IO 线程读取和解析，并用 `analysis` 内的结构化统计生成当前摘要文案；导出同步更新可读摘要和指标说明，原始统计值与保存的检查点保持原样。已保存报告的摘要文案更新无需重新采集。正在采集时需先关闭开关；报告存在状态在读取完成前显示为未知，不用“没有报告”代替加载中。无可读摘要的旧报告会明确提示重新采集，不伪造空白摘要；格式损坏或读取失败会显示错误。预览使用共用的自适应弹窗，正文独立滚动，保留标题和复制/关闭操作，玻璃、MD3 与 Miuix 使用相同内容逻辑。
